## 一、技术环境要求

- 开发语言：Python 3.10+ 

- Web 框架：FastAPI 

- ORM：Tortoise ORM 或者 SQLAlchemy

- 数据库：MySQL

  

## 二、题目内容

### 1. 用户登录与认证

**基础要求：**

1. 实现用户登录接口。支持使用**手机号、用户名或邮箱**中的任意一种作为登录账号（同一输入字段即可），配合密码完成登录。 
2. 登录成功后，向客户端签发一个访问凭证（Token），有效期为 **3 分钟**。 
3. 实现一个受保护的业务接口。该接口必须进行登录状态校验：未登录或凭证已过期时，拒绝访问并返回明确的错误信息；  
4. 校验通过后，返回字符串 `"Hello World"`。

**加分项：**

- 实现双 Token 机制（短效 Access Token + 长效 Refresh Token）。当 Access Token 过期后，可使用 Refresh Token 换取新的 Access Token，无需重新登录。 
- 凭证校验通过 **FastAPI 中间件** 或 **装饰器** 实现。

**期望（非强制，但会作为加分参考）：**

- 密码使用 bcrypt 或 argon2 等安全哈希算法存储，禁止明文或简单 MD5。 

- 接口统一响应格式（建议包含 `code`、`message`、`data` 字段），并合理使用 HTTP 状态码。

  

### 2. 图片上传与处理

**基础要求：**

1. 实现图片上传接口，接收用户上传的图片文件。 
2. 将图片的 R 通道与 B 通道互换（即 RGB → BGR），并将处理后的图片保存至磁盘。

**加分项：**

- 严格校验文件类型，仅允许上传 `png` 或 `jpg`/`jpeg` 格式图片，其他类型文件直接拒绝并返回错误。

**期望（非强制，但会作为加分参考）：**

- 图片处理优先使用 OpenCV 或 Pillow，并在设计文档中简要说明选择理由。 

- 提供简单的接口测试说明（例如 Swagger 文档截图、Postman 示例或 curl 命令）。

  
  
### 3. 异步并发数据聚合接口

**基础要求：**

1. 实现一个受保护的接口（需登录校验，复用第一题的 Token 机制）。
2. 接口接收一个整数参数 n（建议范围 1~10），表示需要并发执行的任务数量。
3. 接口内部必须使用 **异步并发** 方式完成以下模拟任务：
   - 每个任务模拟一次 I/O 操作（使用 asyncio.sleep 模拟耗时，时长可随机或固定，例如 0.5~1.5 秒）。
   - 每个任务返回一个简单的结果（例如任务编号 + 随机数，或固定格式的字典）。
4. **必须使用**并发执行，禁止使用普通 for 循环顺序 await。
5. 所有任务执行完毕后，将结果汇总返回给客户端。
6. 接口整体必须是 async def，并正确处理并发过程中的异常（单个任务失败不应导致整个接口崩溃）。

**加分项：**

- 使用 asyncio.Semaphore 限制最大并发数（例如最多同时运行 3 个任务）。
- 任务执行过程中记录每个任务的实际耗时，并在最终响应中返回总耗时与各任务耗时。
- 合理使用 try/except 对单个任务进行异常隔离，失败任务返回明确错误信息，成功任务正常返回数据。
- 代码结构清晰，将单个异步任务封装为独立的 async def 函数。

**期望（非强制，但会作为加分参考）：**

- 简要说明为什么这里需要异步并发，以及同步顺序执行与异步并发在耗时上的差异。
- 提供接口测试示例（Swagger / Postman / curl），并最好能体现出并发带来的时间优势。
- 统一响应格式，合理使用 HTTP 状态码。
